           32h ago  ●  When you add a second tour to a thread, does a #12.3 in an older message
                       start pointing at nothing? Should a link always say its tour?

△  Not today, since nothing reads format 2's links yet, and it need not once
   prose/ does. Read #12.3 as step 3 of the thread's first tour, always, and
   no link has to say its tour.

   The only link reader in the code now is format 1's, which stage 1 moved
   into prose/init.lua ahead of stage 4. It knows #12 and #12.3. Given
   #1.2.3 it reads #1.2 and leaves .3 as text, so it would open step 2 of
   the first tour instead of step 3 of the second. The check on this step
   shows it. So stage 4 writes a new reader anyway, and the rule is its to
   pick.

   The first tour is safe to default to. thread.tours numbers tours in the
   order of the messages that carry them, and messages are only appended, so
   a tour the agent adds later is always tour 2 or after. Tour 1 never
   moves, and an old #12.3 keeps meaning the step it meant. #12.1.3 would
   read the same, so thread.link can stay as it is.

   Always saying the tour would lengthen every link in a one-tour thread,
   which is most of them: all five threads of
   how-the-model-works-out-its-state have one. It would not guard against
   the bigger risk either. A step inserted into a tour shifts the number of
